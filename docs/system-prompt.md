# System prompt

The default [prompt](../agent/resources/system-prompt.md) defines Trigrams as a general-purpose macOS assistant. It adopts pi's concise tool-driven workflow, progressive skill loading, and project instructions, while adding source boundaries and evidence-based completion. It is written for Trigrams rather than copied from another product's private instructions.

The prompt is an editable preamble, not a replacement for pi's entire assembled context. `DefaultResourceLoader` still supplies discovered skills, project `AGENTS.md`, `SYSTEM.md` / `APPEND_SYSTEM.md`, and the working directory under pi's normal trust and resource rules. Changing or resetting the preamble must preserve those sections.

Settings → System prompt saves the user's version in Trigrams' agent configuration. Reset restores the shipped prompt. Changes apply to the next inference; they do not rewrite persisted messages. The actual effective system prompt can differ from the editor because of project instructions and extension hooks.

The model's instructions guide behavior; they are not an OS sandbox or a replacement for resource trust and distribution policy. Community extensions and scripts execute with the user's permissions.

Foundation Models has a 4096-token context window, shared by instructions, history, generation schema and responses. The shipped preamble is three short paragraphs. A pi `before_agent_start` hook replaces its verbose skill catalogue section with a bounded name preview and the location of a private `skills-index.jsonl`. This generated index retains every enabled model-invocable skill's original description and path. The model searches it with pi's ordinary bash/read tools and reads the selected original SKILL.md in small pages. No descriptions are rewritten by another model, and no source files are edited. Disabled and model-invocation-disabled skills are excluded; explicit `/skill:name` remains pi's normal expansion.

The initial tool loadout is pi's core tools plus tool_search. Codemode is registered with deferred exposure and loaded through pi's existing discovery tool; MCP and user extensions retain their configured exposure. AFM's inference schema uses short descriptions for the core tools; its argument constraints and the sidecar's original-schema validation are preserved. The provider omits billing, timestamps and UI metadata from the inference transcript, while pi's complete JSONL history remains unchanged.

Each inference uses a fresh Apple session. The adapter puts the current user task first, followed by the latest external tool results and explicitly labelled reference history. Earlier assistant tool calls retain their names, IDs and arguments. All earlier messages remain available; pi's canonical history is never rewritten. This order avoids guided generation answering an earlier task when the user changes topic. No executable Apple tools are registered. pi owns history compaction (1536 reserve tokens, 768 recent tokens) and its summary checkpoints. On macOS 26.4+ with a supporting SDK, Apple tokenCount checks instructions, the conversation and the action schema before every generation, with response headroom. macOS 26.0–26.3 preflight the same assembled input and encoded schema using a conservative text estimate, then rely on Apple's overflow errors and pi's compaction. Every completed inference records the separate context budget in pi diagnostics, with measured/estimated provenance; it is not generation usage. Errors use wording recognized by pi's overflow recovery.

A pi tool_result hook pages large direct text results before they enter history or compaction: an estimate above 600 tokens saves the complete original result and text into private 0600 artifacts under the agent directory, and exposes a preview of at most 256 estimated tokens plus a path for offset/limit reads. The estimate treats non-ASCII characters conservatively; it is not reported as measured usage. Structured data remains available to extensions, and nested codemode calls retain their complete results. The chat's Show complete result action reads the original artifact without sending it back into model context. Original files and upstream output limits remain pi's responsibility. At most two direct calls are generated per AFM action; codemode can still batch work.

Oversized custom instructions, explicit giant skill expansions, images, long tool arguments or repeated small results can still exceed the window. The model never silently drops user constraints or project instructions. A context error can require compaction, smaller pages or a shorter custom prompt. Stored artifacts are part of local conversation data and must be retained with its sessions and forks.

Reference: [Apple context window management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).
